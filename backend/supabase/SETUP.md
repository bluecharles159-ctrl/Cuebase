# Cuebase hosted account preparation

This is backend preparation, **not an enabled desktop sign-in feature**. The migration has not been executed against a Supabase project. Cuebase currently uses its local library and host-controlled crew session; this preparation does not upload or migrate those files.

1. Create a Supabase project owned by your production/business, choose its region, and keep its database password private. Apply `001_production.sql` once in the SQL Editor of a fresh project. It creates production ownership, crew roles, isolated channel records and revision-checked content saves. Row-level security prevents another production from reading the records.
2. Enable email authentication with email confirmation. Configure a production SMTP provider before public release. Enable Google and GitHub in Authentication > Providers, using OAuth applications registered by you. Copy the callback URL shown by Supabase into each provider's registration. Provider secrets stay in Supabase, never in the desktop application or GitHub source.
3. Register the desktop return address in Supabase redirect URLs when the desktop callback listener is implemented. Use the system browser and authorization-code PKCE. Validate callback state, exchange the code with the original verifier, store refresh tokens in Windows Credential Manager, refresh sessions, and clear credentials on sign-out. Email recovery/confirmation needs its own tested return flow. These desktop steps are still pending.
4. Desktop configuration needs only the project URL and public publishable key. Do not put a service-role/secret key or database password in Cuebase. No configuration values are embedded in this preparation.
5. After authentication, call `create_production(production_name, channel_name)` for first production setup. It returns the production and exactly one default channel. Additional channels require owner permissions. Collect production name, channel name, optional description/logo and editing-versus-studio mode. Country/time zone, output size/frame rate and output destination are channel settings. RTMP/SRT URL/stream-key secrets remain in the playout host's credential store. Do not upload passwords, stream keys or local absolute media paths as document content.
6. Content synchronization uses `save_channel_document` with channel ID, document ID, kind, previous revision and JSON content. Revision zero creates a document; conflict errors require reloading/merging instead of blind overwrite. Each channel's documents are distinct. `use_shared_settings` is an explicit channel opt-in to production settings; media and scenes are not implicitly shared.
7. Add crew members by authenticated user UUID under an owner's session; viewers can read, editors can save documents, owners manage channels/membership. A secure invitation/acceptance flow and separate graphics/audio UI remain pending. Raw UUID administration is not the intended final user interface.
8. Provision private logo/media storage separately with channel-scoped storage policies. This migration intentionally does not create a public media bucket. Synchronization of actual linked media needs uploads, signed access URLs and a local download cache before another machine can reproduce a scene.

Before enabling the client, test with two users in different productions: unrelated reads return no rows, unauthorized writes fail, viewers cannot save, removed editors lose access, stale revisions fail, simultaneous create conflicts cannot overwrite, and logging out clears local tokens. Test Google, GitHub and confirmed email on two physical devices. None of these hosted checks is claimed as passed yet.

Official references: [Google setup](https://supabase.com/docs/guides/auth/social-login/auth-google), [GitHub setup](https://supabase.com/docs/guides/auth/social-login/auth-github), [PKCE sessions](https://supabase.com/docs/guides/auth/sessions/pkce-flow), [row-level security](https://supabase.com/docs/guides/database/postgres/row-level-security), [private storage access](https://supabase.com/docs/guides/storage/security/access-control).
